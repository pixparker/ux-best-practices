# 🧩 Patterns — *behavior*

Reusable solutions to recurring interaction problems. A pattern describes *what to build* for a given situation — the proven shape of the interaction — independent of styling.

## Planned

**Navigation**
- Bottom navigation vs. tab bar vs. hamburger (when to use which)
- Bottom sheets & the thumb zone
- Breadcrumbs & deep navigation
- Quick navigation / command palette (power users)

**Input & forms**
- Inline validation (validate on blur, not on every keystroke)
- Smart defaults & input masks
- Multi-step forms & progress
- Destructive-action confirmation

**Content & data**
- Empty states (first-run, no-results, error)
- Infinite scroll vs. pagination vs. "load more"
- Search & filtering
- Data tables (sort, filter, bulk actions) — see [ops-panel archetype](../archetypes/ops-admin-panel.md)

**Feedback**
- Toasts & snackbars
- Undo instead of confirm
- Optimistic updates with rollback
