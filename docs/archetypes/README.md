# 📦 Archetypes — *what you're building*

An **archetype** is a product type. Each kind of app has its own center of gravity — what users expect, which patterns matter, and which mistakes hurt most. A playbook here bundles those priorities so you don't re-derive them every project.

> Use it like this: pick your archetype → read its playbook → then layer your [platform](../platforms/) constraints on top.

## The archetypes

| Archetype | Who it's for | Center of gravity |
| --- | --- | --- |
| [Consumer mobile app](consumer-mobile-app.md) | Non-technical, general public | **Simplicity & guidance** — obvious, forgiving, thumb-friendly |
| [Ops / admin panel](ops-admin-panel.md) | Technical / power users | **Speed & density** — tables, filters, keyboard, manage at scale |
| [Fancy app](fancy-app.md) | Consumers wanting delight | **Polish & delight** — few jobs, eye-catching, motion-rich |
| [E-commerce / online shop](ecommerce.md) | Shoppers | **Trust & conversion** — find, decide, buy without friction |
| [Conversational / bot UI](conversational-bot.md) | Chat & assistant users | **Clarity of turn-taking** — guidance, affordances, trust in a chat box |
| [Game app](game-app.md) | Players | **Feedback & flow** — juicy response, onboarding, reward loops *(new — early)* |

> Each playbook follows [`../_TEMPLATE.md`](../_TEMPLATE.md), with a "must do / should avoid" core. The fully-written one so far is **[Ops / admin panel](ops-admin-panel.md)**; the rest are seeds to grow.
